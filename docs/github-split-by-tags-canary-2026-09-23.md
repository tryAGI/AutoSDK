# GitHub.NET split-by-tags canary — 2026-09-23

This canary used the checked-in `src/libs/GitHub/openapi.yaml` from
[`tryAGI/GitHub.NET`](https://github.com/tryAGI/GitHub.NET) at
`b42f0b0cd04fb127956a322c4bc59083ad5944f7`. The existing monolithic SDK
was built from that checkout. The package family was generated from the same
specification with AutoSDK at `f1a939e84a750758ee3c6c0072805bf0aec2beff`.
No packages were published.

## Results

| Measure | Existing monolith | `Core` + `Issues` | Full package family |
| --- | ---: | ---: | ---: |
| Generated C# files | 20,677 | 13,632 | 20,722 across 48 packages |
| Compressed NuGet size | 31.342 MiB | 17.526 MiB | 25.286 MiB total; facade 0.026 MiB |
| Project restore | 4.082 s | 1.901 s | 4.445 s |
| Cold Release build | 117.156 s | 73.561 s | 101.151 s |
| Sampled peak compiler RSS | 17,536.6 MiB | 12,652.1 MiB | 12,218.8 MiB |
| `dotnet pack` with package validation | 5.949 s | Core 3.420 s + Issues 1.131 s | All 48 packages 13.582 s; facade alone 1.731 s |

The `Issues` consumer resolved exactly `tryAGI.GitHub.Issues` and
`tryAGI.GitHub.Core` from a local NuGet feed, built in 1.730 s, and created an
`IssuesClient`. The facade consumer resolved all 48 packages, built in 1.733 s,
and created `GitHubClient.Issues`. Its facade package references the tag packages;
the Core package has no generated package dependency. The Core package contains
13,123 generated files (63.3% of the family), and `Issues` contains 509.

All three measured SDK builds completed with zero warnings and zero errors. The
family build reported no `SYSLIB1031` serializer-context name collisions. All 48
NuGet packages were created with one `Version` value and package validation
enabled.

## Method

- Host: macOS, 128 GiB RAM, .NET SDK 10.0.301; generated projects target
  `net8.0`. Builds used `Release`, `UseSharedCompilation=false`, and
  `--disable-build-servers`. The monolith has one project; its build used
  `-m:1`. The cold family build followed `dotnet clean` and used `-m:8` so tag
  projects could compile in parallel. The focused build used `-m:1`.
- The existing GitHub.NET project disables .NET analyzers and XML documentation
  generation. The new generated projects use their default settings. The
  monolith was generated by an older AutoSDK release, so this comparison also
  includes generator-version differences. It is a rollout canary, not an
  isolated benchmark of the split algorithm.
- Restore measurements used the host's local NuGet cache and local feed.
  They are not measurements of a first download from NuGet.org. Each row is
  one run, with no statistical confidence interval.
- Peak compiler RSS is the largest sampled resident size of a `csc` process,
  not total system memory. `scripts/measure-canary-command.py` samples the
  child process tree every 0.5 s; the focused build's compiler peak was also
  sampled separately at 0.2 s because that run began before the script
  recognized this host's native `csc` executable. The `pack` times include
  `EnablePackageValidation=true`; they do not isolate validation from packing.

Reproduce the generation from an AutoSDK checkout after setting paths for the
matching GitHub.NET checkout and a fresh scratch directory:

```bash
GITHUB_NET_CHECKOUT=/path/to/GitHub.NET
CANARY_OUTPUT=/tmp/autosdk-github-family
dotnet run --disable-build-servers --no-launch-profile --project src/libs/AutoSDK.CLI \
  generate "$GITHUB_NET_CHECKOUT/src/libs/GitHub/openapi.yaml" \
  --namespace tryAGI.GitHub --clientClassName GitHubClient \
  --targetFramework net8.0 --output "$CANARY_OUTPUT" \
  --split-by-tags --package-id tryAGI.GitHub \
  --exclude-deprecated-operations --generate-http-exception-hierarchy \
  --generate-pageable-helpers --generate-retry-handler \
  --use-system-net-http-json --clean-stale-files
```

Use `scripts/measure-canary-command.py --cwd <directory> --log <path>
--result <path> -- <command>` for each restore, build, or pack step. The
result JSON records elapsed time, sampled process-tree RSS, sampled compiler
RSS, command, and exit code. The full family pack command was:

```bash
dotnet pack "$CANARY_OUTPUT/GeneratedPackages/tryAGI.GitHub.slnx" \
  --no-build -c Release -m:1 -p:Version=1.0.0-canary.1 \
  -p:EnablePackageValidation=true -o "$CANARY_OUTPUT/feed"
```

## Rollout boundary

The canary proves that this specification generates and builds as a package
family, that its package dependencies restore from a local feed, and that both
focused and aggregate consumers compile and construct clients. It does not
publish the family or migrate GitHub.NET's release workflow or downstream
consumers. Those changes need a coordinated package-version release so every
tag package and Core are available before the facade is published.
